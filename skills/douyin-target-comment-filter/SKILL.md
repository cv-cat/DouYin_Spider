# 抖音精准目标评论筛选

## 工作流

1. 使用项目 `collect_ip_comments.py`，固定启用 `--region 湖北 --days 14 --target-filter`。`--target-filter` 会自动读取合格评论者主页的公开粉丝量和获赞量。
2. 要求新评论时，用 `--exclude-file` 排除旧批次 ID；旧批次没有 ID 时，同时按规范化评论内容去重。
3. 按 `create_time` 倒序输出。页面只显示相对时间时，不声称同一时间粒度内的精确先后。
4. 报告抓取总量、合格量和淘汰原因分布，不把昵称或文本推断的性别写成已证实身份。
5. API Cookie 不可用时，可复用已登录浏览器读取可见评论 DOM；登录或验证码必须由用户手动完成。

## 硬排除规则

- IP 不是湖北，或发布时间超过 14 天。
- 评论明确询问湖北之外地区的人是否愿意认识、恋爱或交往，例如“郑州的有人谈吗”“南阳有吗”。
- 明确两位出生年份为 `10` 至 `99`。`00` 至 `09` 可保留；未写年份的自然评论不因此排除。
- 内容为空、纯数字、纯年份或只有无意义符号。
- 只有“你好”“我要”“累了”等招呼或态度词，缺少可用客户意向信息。
- 纯表情、纯艾特、“哈哈哈”等语气词，或未体现恋爱、脱单、相亲、认识对象需求的普通互动。
- 明确表达不想恋爱或反对找对象，例如“别找了”“单着不好吗”。
- 主页公开性别为男。
- 评论明确男性自述，如“男大”“男生”“直男”“单身男”“弟弟”“叔”；或明确寻找女性，如“蹲姐姐”“蹲甜妹”“找御姐”“想找女朋友”。
- 昵称以稳定男性称谓构成，如“某某先生”“某某大叔”“某某公子”“某某少爷”。普通“哥”字、英文名或中性昵称不能单独作为硬证据。

确定性实现位于项目根目录 `target_comment_filter.py`。修改规则时必须同步增加 `tests/test_target_comment_filter.py` 正反例并运行测试。

## 准确率信号

以下信号只能结合语境使用：

- 昵称含“叔/弟/先生”，评论又以第一人称求偶，可形成强联合证据。
- 自报身高、房车等条件并明确称自己为“男”“弟弟”“叔”，属于强联合证据。
- “让姐先谈”“姐姐看看我”“缺女友”等明确以女性为目标，呈现明显男性意向。
- 头像、语言风格、游戏偏好、职业、身高本身不能可靠判断性别，不用于硬排除。
- “美女说得对”“姐姐太真实”可能只是称呼作者；只有与“蹲/找/谈/来个”等意向词组合才排除。

## 输出质量

- 每条结果固定输出：排名、发布时间、评论者昵称、评论内容、粉丝量、点赞量、获赞量。
- `follower_count` 为粉丝量，`favoriting_count` 为该用户点赞/喜欢量，`total_favorited` 为该用户获赞量；均来自主页公开数据。
- 粉丝量或获赞量获取失败时显示“未知”，不得用 `0` 代替未知，也不得估算。
- 表格默认列顺序为：`排名 | 发布时间 | 评论者昵称 | 评论内容 | 粉丝量 | 点赞量 | 获赞量`。
- 每次交付统计同一批次的抓取总数、最终合格数和淘汰数；淘汰数等于抓取总数减最终合格数。
- 优先保留有上下文、能体现真实需求或生活处境的自然评论。
- 不输出空评论、纯年份、纯招呼、纯表情等低信息内容。
- 使用评论 ID 去重；缺少评论 ID 时才使用“昵称 + 评论内容”去重。
- 对推断使用“评论呈现明显男性意向”等表述，不将推断包装成人口属性事实。
- 严格规则下不足指定数量时，如实报告，不放宽硬规则凑数。
